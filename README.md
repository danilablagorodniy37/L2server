# L2server — Interlude + Kamael

Кастомная сборка на базе L2J High Five 2.6.3.0-SNAPSHOT: контент откатывается до Interlude,
из поздних хроник остаётся только раса Камаэль. Клиент High Five.

План и статус работ: [TASKS.md](TASKS.md).

## Структура
| Папка | Что это |
|---|---|
| `game/` | Игровой сервер: конфиги, датапак (`data/`), скрипты (`script/`), SQL, библиотеки |
| `login/` | Логин-сервер 2.6.7.3 |
| `core/` | Исходники ядра игрового сервера (Maven). Собранный jar кладётся в `game/l2jserver.jar` |
| `tools/` | Установка базы, сборка ядра, скрипты анализа H5 ↔ Interlude |

Геодата (~900 МБ) в git не хранится. Её нужно скопировать в `game/data/geodata/`
из `L2 SERVER - 2\l2j-server-game-2.6.3.0-SNAPSHOT\data\geodata`.

## Требования
- Java 21
- MySQL 8 на порту 3307, пользователь `root`/`root`
  (меняется в `game/config/database.properties`, `login/config/database.properties` и `tools/db_install.bat`)
- Python 3 — только для скриптов в `tools/interlude/`

## Первый запуск
1. `tools\db_install.bat l2jdb` — создаёт базу `l2jdb_custom` и копирует аккаунты из `l2jdb`
   (без аргумента база будет пустой; аккаунты создаются автоматически при первом входе).
2. `login\startLoginServer.bat`
3. `game\startGameServer.bat` — готов, когда в `game/logs/server.log` появится `Server Bartz loaded in N seconds`.

Рабочий High Five в `L2 SERVER - 2` использует те же порты (2106, 7777, 9014),
поэтому одновременно можно запускать только одну из сборок.

## Резервные копии
`tools\backup.bat` — дамп базы `l2jdb_custom` и копия `system` клиента в `S:\Programming\L2server\backups`, старые копии подчищаются (7 дампов, 3 папки клиента)
(git держит всё остальное: `game`, `core`, `tools`, план). Клиентские файлы, которые правились руками,
лежат рядом с оригиналами: `L2.ini.orig`, `ServerName-*.orig`, `*.bak` из поставки.

`tools\interlude\clean_phantoms.py` — удаляет персонажей ботов сверх `Count` вместе с их предметами
(запускать с остановленным сервером, `--dry-run` показывает, что уйдёт).

`tools\client\backup.bat` — отдельный снимок `system` клиента перед правкой файлов:
`list` показывает снимки, `restore` возвращает последний (или названный). Путь к клиенту
берётся из `L2CLIENT`, по умолчанию `S:\Programming\L2client\HighFive`.

## Тесты
`tools\test.bat` — проверки датапака, скриптов `tools/interlude` и базы (pytest, ~20 с).
`--core` добавляет JUnit-тесты ядра, `--server` — тест запуска серверов. Подробно: [tests/README.md](tests/README.md).

## Боты

443 персонажа без клиента живут в мире: 40 держат лавки в Гиране, 100 живут в городах,
остальные фармят монстров и рейд-боссов. Включается в `game/config/phantoms.properties`,
код — `game/script/com/l2jserver/datapack/custom/phantoms`, данные — `game/data/phantoms`.
Боты — обычные персонажи служебного аккаунта, вход в него закрыт; их реплики пишутся в `game/logs/chat`.

**Охота.** Бот уходит в угодье по своему уровню (35 угодий в `hunting.txt`, построены из зон клиента),
дерётся соулшотами и классовыми скиллами с фиксированным интерлюдным бафом, пьёт зелья, подбирает
добычу и возвращается в город продать лишнее, когда сумка полна. Цели выбирает слабее себя.

**Пати.** Постоянные пати стоят лагерями, список — строки `Camp1..CampN`:

```
Camp1 = 4 9 78 136958 -89946 -3697 Ketra Orc Outpost
```
`<сколько пати> <размер> <уровень> <x> <y> <z> <название>`. В пати есть танк, кардинал, иерофант,
танцовщицы, лучники и дуэлист в S-грейде с бижу и +6. Лекарь лечит, павших поднимают на месте,
баферы держат бафы, раз в полчаса пати уходит на рейд-босса своего уровня. Половина пати на земле —
отход в город на 3 минуты. Ещё 20 малых групп по 2–4 бота охотятся вместе в зонах по уровню.

**Разговор.** Ответы игроку пишет локальная модель через Ollama (`llama3.2`, настройки `Llm*`):
в промпте — имя, уровень, класс, чем бот занят и где, и последние 6 реплик диалога. Модель занята
или выключена — бот отвечает из `phrases.txt`. Боты говорят о том, что произошло: убитый рейд-босс,
смерть или новый уровень рядом, осада, олимпиада, новый клан. Без событий молчат, кроме редких
реплик в городе. На приглашение в группу и в клан отвечают через несколько секунд, на трейд — зовут
в свою лавку.

**Наблюдение.** Раз в 5 минут в лог идёт отчёт: кто где, убийства, смерти, проданная адена,
состояние каждой пати, доля ответов модели и время тактов. В игре — GM-команда `//bots`
(страница со сводкой и переходом к лагерю любой пати) и страница «Bot Hunting Grounds»
в меню телепортов.

| Файл данных | Что в нём |
|---|---|
| `phrases.txt` | реплики по секциям: события, диалоги, ответы на приглашения |
| `hunting.txt` | угодья: координаты, уровни, сколько монстров, название зоны |
| `zones.txt` | зоны карты клиента (`tools/client/hunting_zones.py`) |
| `gear.txt` | снаряжение по грейдам (`tools/interlude/build_phantom_gear.py`) |
| `trade.txt` | товар лавок (`tools/interlude/build_phantom_trade.py`) |

## Админка
`//panel` — одна страница про этот сервер: сколько он на ногах, кто в мире (игроки отдельно, боты отдельно),
рейты и память; все восемь эпиков Interlude — стоит, лежит и сколько осталось, кнопка «Go» к логову каждого;
сколько рейд-боссов стоит из скольких; чем заняты боты; и кнопки на каждый день — скорость, невидимость,
неуязвимость, лечение, воскрешение, перезагрузка HTML и список угодий ботов. Кнопка «Panel» добавлена
в верхний ряд всех меню GM, `//bots` открывается оттуда же.

`//config` (кнопка Settings) показывает, на что настроен сервер: кап уровня, рейты, какие системы поздних
хроник выключены. Изменить на ходу можно только то, что лежит в `server`, `general` и `geodata`
properties (`//set <параметр> <значение>`), остальное читается один раз при старте — страница об этом говорит.

Из меню GM убраны системы, которых на сервере нет: Territory War, Gracia, Hellbound, инстансы и Vitality
(проверка `admin_menu_buttons` следит, чтобы они не вернулись).

## Клиент
Файлы клиента в git не хранятся: `S:\Programming\L2client\HighFive` (путь меняется переменной `L2CLIENT`).

| Скрипт | Что делает |
|---|---|
| `tools\client\backup.bat` | снимок `system` перед правкой, `list` и `restore` |
| `tools\client\clean_ini.py` | чистит `L2.ini` (чужой итем-молл, автологин, адрес сервера); `--list` показывает весь файл |
| `tools\client\l2dat.py` | чтение и запись клиентских `.dat`/`.ini` (Ver111/Ver413, CRC) |
| `tools\client\xdat.py` | разбирает `Interface.xdat`: окна, виджеты, системы поздних хроник, вырез |
| `tools\client\xdat_layout.py` | структура `Interface.xdat`: виды записей, кто кого держит, где счётчик детей |

**Как читается `Interface.xdat`.** Файл — плоский список записей: вид виджета строкой, сразу за ним имя,
дальше ещё строки и числа. Раньше список видов был захардкожен, и это ровно то, на чём сломался
пробный вырез 19.09: виды записей, которых в списке нет, в файле есть, из-за них соседние записи
слипаются, и вырезанные байты оказываются не границами виджета.

Теперь ничего не угадывается. Из файла выводятся три вещи — какие строки являются видами записей,
какой вид держит остальные и где внутри его записи лежит счётчик детей. Мерило одно:

> файл прочитан правильно, когда у каждого окна число детей, записанное в файле, совпадает с числом
> записей, которые за ним действительно идут

Лишний вид добавляет записи внутрь окна, и счётчик выходит больше реального; пропущенный вид
записи склеивает, и счётчик выходит меньше. Поэтому кандидаты в виды берутся по признаку «справа
приклеено имя, слева ничего не приклеено» (имя виджета ведёт себя наоборот), затем лишние
отбрасываются, а недостающие ищутся прицельно — внутри тех окон, которые не досчитались.
Позиция счётчика перебирается до 64 байт от конца записи и от последней строки, отдельно
проверяется вариант, где счётчик включает само окно.

**Вырез.** Окно не удаляется — оно опустошается: запись самого окна остаётся на месте, уходят только
его дети, счётчик становится нулём. Окно, которое не сходится само, не трогается никогда: там
неизвестно, где кончаются виджеты. Готовый файл перечитывается тем же разбором и сверяется с
исходным: те же окна, дети только у тех, кого не резали, ни одно сходившееся окно не разъехалось.
Не сошлось — файл не пишется.

Порядок работы:
1. `tools\client\backup.bat` — снимок, к которому можно вернуться.
2. `python tools\client\xdat.py --check` — что вычитано из файла: сколько видов записей, кто держит
   детей, где лежит счётчик, сколько окон из скольких сходится, есть ли в файле ссылки на смещения
   записей (если есть — двигать ничего нельзя, и вырез откажется).
3. `python tools\client\xdat.py --dump --json out.json` — если сходятся не все окна: заголовок,
   каждая запись со своими байтами, список несошедшихся. По этому дампу разбор дорабатывается.
4. `python tools\client\xdat.py --cut-systems --out new.xdat` — вырез всех окон выключенных систем.
   Если сходятся не все окна, добавить `--force`: тогда режутся только те окна, которые сходятся,
   а про остальные скрипт скажет, что оставил их как есть.

## Сборка ядра
`tools\build_core.bat` — собирает `core/` через Maven Wrapper и копирует `l2jserver.jar` в `game/`.
Скрипты из `game/script/` сервер компилирует сам при запуске, для них сборка не нужна.
Скрипты датапака компилируются один раз в `game/cache/scripts` и дальше читаются оттуда;
кэш сам протухает, когда меняется исходник скрипта или `l2jserver.jar`.

## Откат до Interlude
Скрипты в `tools/interlude/` сравнивают датапак с aCis
(`../acis_public-master/aCis_datapack`, путь меняется переменной `ACIS_DATAPACK`)
и вычищают контент поздних хроник. Что считается камаэльским контентом, задано в `kamael.py`.

| Скрипт | Что делает |
|---|---|
| `analyze.py` | Отчёт: сколько предметов, NPC, скиллов и спавнов H5 нет в Interlude |
| `build_skill_trees.py` | Деревья скиллов классов по aCis, Камаэли до 80 уровня |
| `build_skill_stats.py` | Значения скиллов (расход, откат, сила, длительность) из aCis |
| `build_enchant_costs.py` | Цена (SP и опыт) и шансы заточки скиллов по таблицам Interlude |
| `build_residence_skills.py` | Скиллы резиденций только у крепостей: у замков и территорий убраны |
| `build_spellbooks.py` | Книги для изучения скиллов и их продажа в магазинах |
| `build_npc_stats.py` | Статы, уровень и опыт монстров и боссов как в Interlude (пересчёт под формулы ядра H5) |
| `build_drops.py` | Дроп и спойл монстров из aCis |
| `build_quests.py` | Убирает квесты поздних хроник из `QuestLoader` |
| `build_ai.py` | Убирает AI-скрипты поздних зон и систем из `AILoader` |
| `build_spawns.py` | Чистит `spawnlist.sql`, переносит монстров Interlude из aCis |
| `build_minions.py` | Возвращает лидерам миньонов Interlude (`privates` aCis) в шаблоны NPC и в `MinionSpawnManager` |
| `build_shops.py` | Чистит магазины и мультиселлы |
| `build_items.py` | Чистит дроп, рецепты, стартовую экипировку |
| `build_teleports.py` | Убирает телепорты в поздние зоны и ссылки на них в HTML |
| `fix_teleports.py` | Телепорты для дворян за Noblesse Gate Pass, точки прибытия и цены Interlude |
| `build_bosses.py` | Убирает поздних рейд- и эпик-боссов |
| `build_html_links.py` | Убирает из диалогов NPC кнопки удалённых магазинов и мультиселлов, а из `data/html` — кнопки незагруженных квестов и AI-скриптов |
| `build_phantom_gear.py` | Снаряжение ботов: оружие и комплекты брони из предметов Interlude и Камаэлей |
| `fix_floating_spawns.py` | Опускает на пол геодаты спавны, висящие в воздухе; висящих рейд-боссов ставит в центр их территории aCis |
| `port_quest_html.py` | Переносит диалоги квеста из aCis в папку квеста H5 |
| `validate.py` | Печатает проверки из `checks.py` (те же, что в тестах): битые ссылки, остатки поздних хроник, `--db` сверяет базу с `game/sql` |

Скрипты уже применены, результат в git. Они рассчитаны на исходные файлы H5:
повторный запуск на уже очищенных данных почти везде безопасен, но `build_skill_trees.py`
нужно запускать только на исходном файле (`git checkout <коммит импорта> -- <файл>`).
После изменения SQL-файлов таблицы в базе нужно перезалить.
